## 1. 画像と補完のキホン

<a id="pixel-channel-tensor"></a>

### ピクセル・チャネル（`3ch` / `11ch`）・テンソル

- **一言でいうと**: プログラムから見た画像は「縦 × 横 × レイヤー数」の 3 次元配列（テンソル）であり、チャネル（`ch`）は同じ位置に重なった情報レイヤーの枚数です。
- **具体例・イメージ**:
  - 普通のカラー写真（RGB）は、同じ横幅・高さの「赤の濃さ」「緑の濃さ」「青の濃さ」の 3 枚の透明シートを重ねたもので、これを **3 チャネル（`3ch`）** と呼びます。
  - 深層学習では色だけでなく、「その画素が欠損していないか（0 か 1）」「そこが海か陸か」といった補助データも**同じ大きさの透明シート（チャネル）**として横に積み重ねてモデルに渡せます。
- **このプロジェクトでの役割**: 主力モデル `PrevImageGuidedResSEUNet` に渡す `11ch` 入力は、以下の 11 枚のシートを 1 箇所の座標 `(y, x)` に束ねたものです（PyTorch の 4 次元配列 `[バッチ枚数, 11, 64, 64]` を**テンソル**と呼びます）。

```text
[11ch 入力テンソルの中身（1つの座標 (y, x) に 11 個の数値が重なる）]
  ch 0..2 : 当日の観測画像 (Ch1可視, Ch2近赤外, Ch4赤外) ※欠損部は 0
  ch 3..5 : 観測マスク     (各チャネルが受信できていれば 1.0, 欠損なら 0.0)
  ch 6..8 : 前イメージ     (別日の晴天METEOR + ひまわり較正アトラスの 3波長)
  ch 9    : 陸地確率       (海 0.0 〜 陸 1.0 のなめらかな地図)
  ch 10   : 沿岸エッジ重み (海岸線の周囲数pxだけ 1.0 に光る帯)
```

<a id="smoothing"></a>

### 平滑化（ボケる・ならされる）とは何か

- **一言でいうと**: 隣り合うピクセル同士の値を混ぜて平均化し、くっきりした境目や細かなザラザラ感を「すりガラス越し」のようにぼかす処理（または結果としてそうなる現象）です。
- **具体例・数値計算**:
  横 1 列に並んだ 4 ピクセルの明るさ（`0`＝真っ黒、`255`＝真っ白）を考えます。
  - **くっきりした境界（海岸線や雲の縁）**: `[0, 0, 255, 255]`
  - **隣と 1:1 で平均する平滑化を 2 回かけると**:
    - 1 回目: `[0, 85, 170, 255]`（境目がなだらかな坂道になる）
    - 2 回目: `[42, 113, 141, 212]`（さらにのっぺりした灰色に近づく）
- **このプロジェクトでの役割**: 衛星画像の海（暗い）と雪や雲（明るい）の境目が平滑化されると、**「本当は 1px 幅でクッキリ分かれている樺太の海岸線」が、ぼんやりした霧のかかった灰色帯**になってしまいます。本プロジェクトの工夫の多くは「欠損を埋めつつ、この平滑化（ボケ）をどう防ぐか」に注がれています。

---

<a id="bilinear"></a>

### バイリニア補間（Bilinear Interpolation）

- **一言でいうと**: 欠損したピクセルの周囲にある生きているピクセルから「距離に応じた割り算（グラデーション）」で値を埋める、もっとも古典的で単純な補間計算です。
- **具体例・数値計算**:
  高さ 4px の水平黒帯を挟んで、上端のピクセルが明るさ `200`（白い雲）、下端のピクセルが明るさ `0`（暗い海）だったとします。バイリニア補間（縦方向だけ見れば線形補間）では、間の 3 行を距離比で等分するだけです。

```text
  上端（実測）: 200  ████████  ← 白い雲
  欠損 1 行目 : 150  ▓▓▓▓▓▓▓▓  (= 200 * 3/4 + 0 * 1/4)
  欠損 2 行目 : 100  ▒▒▒▒▒▒▒▒  (= 200 * 2/4 + 0 * 2/4)
  欠損 3 行目 :  50  ░░░░░░░░  (= 200 * 1/4 + 0 * 3/4)
  下端（実測）:   0  ........  ← 暗い海
```

- **なぜこれではダメなのか（このプロジェクトでの限界）**:
  - ただ上下の端を直線グラデーションで繋ぐだけなので、**黒帯の途中に海岸線や島や渦巻く雲があっても絶対に復元できません**。
  - 幅が `40〜96 px` ある黒帯に使うと、上の画素と下の画素が縦方向に長く引き伸ばされた「バーコード状の縞模様」や「ぼんやりしたグラデーション」になってしまいます。

<a id="inpainting-ssl"></a>

### インペインティング（Inpainting）＆ 自己教師あり学習（Self-Supervised Learning）

- **一言でいうと**: インペインティングは「画像の一部を欠損させて元通り修復する穴埋め技術」、自己教師あり学習は「人間が正解ラベルを作らなくても、無傷の画像に自分で穴を開けて問題集を自動生成して学ぶ学習方法」です。
- **具体例・イメージ**:
  - METEOR-M2 の観測画像には「ここが雲の正解画像です」という教師データは付属していません。
  - そこで、**「ちゃんと受信できている部分（または雲のないひまわり画像）」の一部をプログラムで黒く塗りつぶし、「塗りつぶす前の元画像」を答え合わせの正解として AI に穴埋め問題を解かせる**ことで、人間が 1 枚も手作業でラベル付けすることなく何千問もの学習データを作れます。
- **このプロジェクトでの役割**: Notebook `02` からずっとこの方式を採用しています。本番の受信環境に近い「片方のバンドだけ消す」「幅 `36〜58 px` を丸ごと消す」「端の数行だけ残して `95%` 消す」といった疑似マスクを GPU 上で毎ステップ自動生成して鍛えています。

<a id="loss-avg-blur"></a>

### 損失関数（L1 / Charbonnier）と「条件付き期待値による平均ボケ」

- **一言でいうと**: 学習時に「正解ピクセルとのズレを減らせ（L1 損失）」とだけ命令すると、AI が「外したときの減点を最小にするために、あえて無難な中間色（灰色）を答える」現象が起きます。
- **具体例・数値計算（なぜ灰色になるのか）**:
  ある欠損ピクセルについて、周囲の状況から「50% の確率で海（明るさ `20`）」、「50% の確率で厚い雲（明るさ `220`）」だとします。AI にピクセルごとの絶対誤差（$| \text{予測} - \text{正解} |$、これが **L1 損失**）の平均を最小にする問題を出したとき、どの値を答えるのが一番得でしょうか？
  - **AI がギャンブルして「雲 (`220`)」と答えた場合**:
    - 正解が雲なら誤差 `0`、海なら誤差 `200` → 期待誤差 = `0.5 * 0 + 0.5 * 200 = 100`
  - **AI が真ん中の「ぼんやりした灰色 (`120`)」と答えた場合**:
    - 正解が雲でも誤差 `100`、海でも誤差 `100` → 期待誤差 = `100`（二乗誤差の L2 損失なら、灰色のほうが `10,000 < 20,000` と圧倒的に有利）
  - このように、正解が 1 つに絞れない状況で誤差最小化だけを追求すると、数理的に**あり得る候補の平均値（条件付き期待値）＝ボケた灰色**を出力するのが正解になってしまいます。
  - なお、**Charbonnier 損失**は L1 損失 $|d|$ の `0` 付近（折れ曲がって微分できない角）を $\sqrt{d^2 + 10^{-6}}$ でわずかに丸めた、学習が安定しやすい L1 の親戚です。
- **このプロジェクトでの役割**: Notebook `02〜06` で L1 系損失だけを使ったとき、欠損ギャップの中心が滑らかな灰色や濁った緑色に霞む原因がまさにこれでした。そのため Notebook `07〜09` では後述する **Sobel 勾配損失** や **PatchGAN** を組み合わせ、「平均点を取る灰色回答」を禁止してクッキリした線や雲粒を描かせるようにしました。

## 2. ニューラルネットの仕組み（U-Net から最新モデルまで）

<a id="conv-receptive-field"></a>

### 畳み込み（Convolution）と受容野（Receptive Field）

- **一言でいうと**: 「畳み込み」は `3×3` マスの小さな虫眼鏡を画像の上でスライドさせながら周囲の特徴（縦線、丸み、明るさ）を拾い上げる計算で、「受容野」はその計算結果 1 マスが見渡せている元画像の広さです。
- **具体例・イメージ**:
  - 1 層目の畳み込みでは、1 つの出力マスは元画像の `3×3 px`（ごく狭い範囲）しか見られません。
  - 画像を 1/2 に縮小してからさらに `3×3` をかける（層を深くする）と、見ている範囲（受容野）は `6×6`、`12×12`、`24×24`……と倍々に広がります。
- **このプロジェクトでの役割**: もし黒帯の幅が `96 px` あると、受容野が `32 px` しかないモデルでは、ギャップのど真ん中から上端・下端の実測ピクセルがまったく見えず、何を基準に埋めていいか分からなくなります。これが後述の **U-Net** や **Onion-Peel**、**2×広域融合** が必要になる物理的な理由です。

---

<a id="unet"></a>

### U-Net（なぜ U の字なのか・スキップ接続とは）

- **一言でいうと**: 「画像をどんどん小さく縮めて全体の意味（どこに大陸や低気圧があるか）を掴み（下り）、元の大きさへ引き伸ばして描き戻す（上り）構造」に、「縮小前の細かい輪郭メモを横渡しするショートカット（スキップ接続）」を付けた画像変換の定番モデルです。
- **図解（処理の形がアルファベットの U になる）**:

```text
入力 (64x64) ──[畳み込み e1]──────────────────────(スキップ接続)──────────────────────▶ [合流 d1] ──▶ 出力 (64x64)
                    │                                                                    ▲
                 1/2縮小                                                             2倍拡大
                    ▼                                                                    │
                 [e2 (32x32)] ────────────────────(スキップ接続)────▶ [合流 d2] ─────────┘
                    │                                                    ▲
                 1/2縮小                                             2倍拡大
                    ▼                                                    │
                 [最深部・ボトルネック b (16x16)] ────────────────────────┘
                 （全体の文脈・雲や地形の配置を大局的に理解する場所）
```

- **なぜスキップ接続（横渡し）が必要なのか**:
  - もし下り階段で `16×16` まで縮小した情報だけから `64×64` を描き直すと、大まかな位置は合っても「1px 単位の細かい位置情報」が縮小時に潰れてしまい、全体がボケます。
  - **スキップ接続**で「縮める前の鮮明な特徴マップ」を同じ解像度の上り階段へ直接バイパスすることで、「大局的な判断（深層）」と「細かいピクセル位置（浅層）」を合体させてシャープな画像を出力できます。
- **このプロジェクトでの役割**: `02` の軽量版 `MiniUNet` から `11` の `PrevImageGuidedResSEUNet` まで、全モデルの骨格が U-Net です。

---

<a id="resse"></a>

### Residual（残差接続）＆ SE（Squeeze-and-Excitation）

- **一言でいうと**:
  - **Residual（残差接続）**: 「入力を丸ごと作り直す」のではなく、「元の入力に『修正すべき差分（プラスマイナス）』だけを足し算する」構造です。
  - **SE（Squeeze-and-Excitation）**: 「今はどのチャネル（特徴）を重視し、どれを弱めるべきか」を音響ミキサーのフェーダーのように自動で重み付けする注意機構（Attention）です。
- **具体例・イメージ**:
  - ネットワークが深くなると、入力情報が奥まで届きにくくなります（勾配消失）。`output = input + Conv(input)` のように入力そのものを足し戻す（ショートカットを作る）だけで、「そのまま通せばゼロからやり直さずに微調整できる」ため、学習が劇的に安定します。
  - `SE` は各チャネルの平均値を 1 回ギュッと圧縮（Squeeze）して、「今は雲より海岸線の特徴チャネルを `0.9` 倍、ノイズ気味のチャネルを `0.1` 倍にしよう」という重み（Excitation）を掛けて調整します。
- **このプロジェクトでの役割**: Notebook `05` で導入した `FastResSEBlock` はこの 2 つを組み合わせており、精度を落とさずに 1.6M パラメータ級のモデルを Apple M2 の MPS 上で高速学習できるようになりました。

---

<a id="pyramid"></a>

### マルチスケール文脈集約（`PyramidContextBottleneck`）

- **一言でいうと**: U-Net の一番底（`16×16`）で、「1 マス単位（`1×1`）」「`3×3` 視野」「`4×4` まとめ（広域）」「画像全体の平均（超広域）」という 4 通りの虫眼鏡を並列にかけて合流させる層です。
- **このプロジェクトでの役割**: 衛星写真では「手元の細い谷や雲の縁」と「画像全体を貫く大きな前線の向きや北海道の大きさ」を同時に見る必要があります。Notebook `07` で導入したことで、大きな欠損帯をまたいだ大陸の繋がりが途切れにくくなりました。

---

<a id="prior-gate"></a>

### Prior（事前知識）＆ `PriorGateFusion`

- **一言でいうと**:
  - **Prior**: AI が推論するときのヒントとして、あらかじめ外部から渡す「前提知識・カンニングペーパー」（この座標は陸か海か、海岸線はどこか等）です。
  - **`PriorGateFusion`**: 「入口」で渡した Prior を U-Net の「出口直前」でもう一度照合し、大事な境界線だけを通すチェックゲートです。
- **具体例・イメージ**:
  - 人間でも、白黒の一部隠れた航空写真だけを見て海峡を描くのは難しいですが、横に「地図帳の海岸線（Prior）」があれば正確に線を引けます。
  - ただし U-Net の入口に地図を渡しただけでは、中間層を通るうちに 1px の境界線が少しずつ曖昧になります。そこで出口の直前に置いた `PriorGateFusion` が「ここは海岸線（`coast_edge` が高い）だからこの特徴を通す／ここは海だから通さない」と 0〜1 のゲートで再制御します。
- **このプロジェクトでの役割**: Notebook `08` で導入した結果、幅 `88〜96 px` の全欠損ギャップ内部での海岸線勾配保持率が **`6.4% → 54.7%`** へと劇的に向上しました。

<a id="trust-gate"></a>

### Temporal Trust Gate（空間時系列信頼ゲート）

- **一言でいうと**: 11ch モデルがピクセルごとに「今日の観測から描いた映像」と「過去の晴天地図（前イメージ）」を何％ずつ混ぜるか自動で決めるフェーダー（スライダー）です。
- **数式と具体数値イメージ**:
  モデルは以下の式で、すべての画素ごとに $\alpha_{\text{prev}} \in [0, 1]$ を出力します。

  $$\hat{I} = I_{\text{obs}} \odot M + \Big[(1 - \alpha_{\text{prev}}) \odot I_{\text{net}} + \alpha_{\text{prev}} \odot I^{\text{prev}}\Big] \odot (1 - M)$$

  - **受信できた場所（$M = 1$）**: 左側の $I_{\text{obs}} \odot M$ だけが生き、右側は $\times 0$ で消えるため、**実測データは 1 ミリも改変せずそのまま出力**します。
  - **欠損していて、上下に厚い雲が繋がっている場所（$M = 0$）**: モデルは $\alpha_{\text{prev}} \approx 0.05$ を出し、`95%` を当日の雲再構成 $I_{\text{net}}$ にして今日の雲を自然に繋ぎます。
  - **欠損していて、晴天または `90%` 欠損のように周辺情報がない場所（$M = 0$）**: モデルは $\alpha_{\text{prev}} \approx 0.90$ を出し、過去の正確な地表・山脈・海岸線 $I^{\text{prev}}$ を土台として活かします。

<a id="sec-3"></a>

## 3. ボケを防ぎ、リアルな輪郭と質感を出すテクニック

<a id="sobel-fft"></a>

### Sobel 勾配損失（エッジ）＆ 2D-FFT 周波数損失（模様の細かさ）

- **一言でいうと**: 「ピクセルの色の明るさ」だけでなく、「隣との明るさの差（輪郭のクッキリさ＝Sobel）」や「細かい模様の量（周波数成分＝2D-FFT）」も正解と一致させるための追加スコア基準です。
- **具体例・イメージ**:
  - **Sobel 勾配（微分）**: 隣のピクセルとの引き算です。海岸線など急激に色が変わる場所では値が大きくなり、ボケてなだらかになると値が小さくなります。「Sobel の大きさを正解に近づけろ」と学習させることで、AI が境界をぼかして逃げられなくなります。
  - **2D-FFT（2 次元高速フーリエ変換）**: 画像を「ゆっくりした明るさの変化（低周波＝海や空のベース）」と「細かいチリチリした変化（高周波＝雲粒や山の凹凸）」の波に分解します。高周波成分が正解より減っていたらペナルティを与えることで、ツルツルに平滑化されるのを防ぎます。
- **このプロジェクトでの役割**: Notebook `07` で導入し、単なる L1 損失モデルで見られた「ぼんやりした輪郭」をくっきり引き締めました。

---

<a id="patchgan"></a>

### PatchGAN・識別器・Spectral Norm・Feature Matching

- **一言でいうと**: 「本物そっくりの絵を描く画家（生成器）」と「本物の写真か AI の偽物かを小マス目（パッチ）ごとに見破る鑑定士（識別器）」を競わせて、L1 損失の灰色ボケを根絶する手法（GAN）です。
- **なぜ灰色ボケが消えるのか**:
  - L1 損失だけだと「雲か海か分からないから真ん中の灰色」を出せば無難にやり過ごせました。
  - しかし **PatchGAN** の識別器は、「`30×30 px` の小領域の中に、そんなのっぺりした灰色は本物の衛星写真には存在しない！偽物だ！」と即座に見抜いて減点します。その結果、生成器は本物らしい雲粒や地形の凹凸を描くようになります。
- **安定化のための 2 つの安全装置（GAN は学習が不安定になりやすいため必須）**:
  - **Spectral Normalization (Spectral Norm)**: 識別器の重み行列の最大拡大率（特異値）を `1` に抑え、鑑定士が強くなりすぎて学習が発散するのを防ぐリミッターです（PyTorch MPS で標準実装の `aten::vdot` が未対応だったため、本プロジェクトでは MPS ネイティブに自作 `MPSSpectralConv2d` を実装しています）。
  - **Feature Matching 損失**: 識別器が出す最終的な「本物/偽物」スコアだけでなく、識別器の途中 3 層で反応した特徴マップ同士を近づけることで、破綻した幻覚（ハルシネーション）を抑えつつ質感だけを似せます。
- **このプロジェクトでの役割**: Notebook `09`（策C）で導入し、沿岸勾配保持率 `83.2%` とリアルな微細質感の生成を実現しました。

---

<a id="texture-transfer"></a>

### Contextual 微細質感転写

- **一言でいうと**: 補完した後のちょっと滑らかな領域に対して、**同じ衛星写真内の無傷な場所から「似た色・陸海条件の細かなザラザラ成分」を探して移植する**仕上げ処理です。
- **具体例・イメージ**:
  1. 画像全体から「ボケた低周波ベース」を引き算して、「細かな粒状成分（高周波ノイズ・地形テクスチャ）」だけを取り出します。
  2. 補完した `16×16` タイルと、平均輝度や陸海割合が似ている無傷の `16×16` タイルを検索し、その粒状成分だけを軽く重ねます（海岸線の 1px 境界線の上は崩さないよう弱めます）。
- **このプロジェクトでの役割**: 8ch 単体補完モデル（`nb09`）の推論後処理として動作し、深層学習モデルが出しがちなわずかな平滑さを本物のセンサー粒状感に馴染ませています。

<a id="sec-4"></a>

## 4. 学習・位置合わせ・推論・評価のエンジニアリング

<a id="transfer-learning"></a>

### 事前学習（Pretraining）＆ ファインチューニング（Fine-Tuning）

- **一言でいうと**: 先に「大量の似たデータ」で基礎を勉強し（事前学習）、あとから「少量の本当に解きたいデータ」で最終調整する（ファインチューニング）2 段階学習です。
- **このプロジェクトでの役割**:
  - 手元で綺麗に受信できた `METEOR-M2` の画像枚数だけでは、何千枚も必要な深層学習モデルをゼロから育てるには足りません。
  - そこで Stage 1 として公開されている **ひまわり 8 号（5 シーン）** の大量パッチで「東アジアの雲・陸・海・海岸線の一般的な見方」を覚えさせ、Stage 2 として **METEOR-M2 実測データ** でセンサー特有の色味や欠損パターンへ微調整しています。

---

<a id="registration-tps"></a>

### レジストレーション（位置合わせ）・Powell 最適化・Thin-Plate Spline (TPS)

- **一言でいうと**:
  - **レジストレーション**: 斜めに飛ぶ衛星画像と基準の地図画像を、ピクセル座標レベルでピタリと重ね合わせる処理です。
  - **Powell 最適化**: 微分（傾き）の式が書けない複雑な一致度スコアを、パラメータを順番に少しずつ動かしながら最大化する探索アルゴリズムです。
  - **Thin-Plate Spline (TPS)**: 薄い金属板の数箇所をピンで留めて曲げるように、画像全体の座標を滑らかにたわませる非線形変換です。
- **なぜ単純な平行移動では合わないのか**:
  極軌道衛星は南西〜北東などに傾いて飛び、さらに地球が丸いため画像の左右端に行くほど横方向に歪みます。本プロジェクトでは以下の 2 段階で自動位置合わせしています。
  1. **Stage 1（大域位置合わせ）**: 平行移動・回転・拡縮＋走査歪み（$u^3$ 項）のパラメータを **Powell 法** で最適化し、晴天の陸海シルエットを重ねます。
  2. **Stage 2（局所微調整）**: 沿岸タイルの微小ズレ（数ピクセル単位の揺らぎ）を自動検出し、**TPS** で局所の歪みを滑らかに吸収します（`20261026` や `20261027` で晴天一致率 `92〜95%` を達成）。

---

<a id="onion-peel"></a>

### Onion-Peel（玉ねぎの皮むき）段階推論

- **一言でいうと**: 大きな空白を 1 回で一括塗りつぶしせず、実測と接している外側のフチから「玉ねぎの皮を 1 枚ずつ巻くように」少しずつ内側へ埋めていく推論方法です。
- **図解（幅 96 px の黒帯を 4〜5 回に分けて閉じるイメージ）**:

```text
初期状態 (Phase 0後) : [実測] ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ [実測]
Step 1 (±11px 前進)  : [実測][既復元] ░░░░░░░░░░░░░░░░░░ [既復元][実測]
Step 2 (±11px 前進)  : [実測][  既復元  ] ░░░░░░░░░░ [  既復元  ][実測]
Step 3 (中央閉塞)    : [実測][        既復元領域（接続完了）        ][実測]
Phase 2 (両岸再整合) : [実測][   左右・上下を同時に見て中央を再仕上げ  ][実測]
```

- **このプロジェクトでの役割**: 推論単位である `64×64` パッチの視野内に常に実測（または既復元）のヒントが入る状態を保てるため、`96 px` や `128 px` の巨大な空白でも途中で方向を見失わずに両岸の海岸線を接続できます。

---

<a id="tta"></a>

### 4-way Flip TTA（Test-Time Augmentation）

- **一言でいうと**: 推論時（テスト時）に同じパッチを「そのまま」「左右反転」「上下反転」「180度回転」の 4 パターンでモデルに解き直させ、向きを元に戻してから 4 つの答えを平均する手法です。
- **このプロジェクトでの役割**: モデルの再学習なしに推論精度（PSNR でおよそ `+0.1 dB` 程度）とタイリング境界の滑らかさを安定させるために使います。CLI では `--quality high` 指定時に有効になります（計算量は 4 倍になるため、標準モード `--quality standard` では高速な 2-way 左右反転平均を使用）。

---

<a id="leave-one-out"></a>

### Leave-One-Out（データリーク防止）

- **一言でいうと**: 「テスト問題を出題するとき、参考書の中からテスト対象自身のページを必ず破り捨てておく」という機械学習の基本ルールです。
- **このプロジェクトでの役割**: 時系列モデル（11ch）では過去の METEOR-M2 パスの晴天画像をアトラスに焼き込んでガイドに使いますが、たとえば `20261026` の画像を補完・評価するときに `20261026` 自身の画素がアトラスに混ざっていたら「答えを見ながらカンニングしている（データリーク）」ことになります。本パイプラインでは `build_leave_one_out_prev_atlas` により推論対象パス自身を必ずプールから除外しています。

---

<a id="metrics"></a>

### 評価指標の読み方（Hole L1 / PSNR / Sobel 保持率 / Seam Jump）

モデルが良くなったかを感覚ではなく数字で判断するため、以下の 4 つの指標をベンチマークにしています（`↑` は大きいほど良い、`↓` は小さいほど良い）。

| 指標 | 意味と読み方 | 本プロジェクトでの目安 |
| :--- | :--- | :--- |
| **Hole L1** (`↓`) | **欠損領域だけ**における正解画素値（`0.0〜1.0`）との平均絶対誤差。全体を含めると無傷の画素が平均を薄めてしまうため、あえて穴の中だけで測ります。 | `0.0793`（Notebook `02`）→ `0.025〜0.028`（`06〜11`）。約 1/3 まで誤差を圧縮。 |
| **PSNR [dB]** (`↑`) | Peak Signal-to-Noise Ratio。誤差の二乗を対数（デシベル）で表した画質指標です。対数スケールなので `+1〜3 dB` でも見た目は大きく変わります。 | `18.7 dB`（ぼんやり再現）→ `28.0〜28.7 dB`（細部まで鮮明な再現）。 |
| **Sobel 保持率 [%]** (`↑`) | 正解画像のエッジ勾配の強さに対して、補完画像にどれくらい鋭い輪郭が残っているかの比率です（PSNR だけでは測れない「ボケなさ」を評価）。 | `6.4%`（`08` 比較基準）→ `54.7%`（`08` 策B）→ **`83.2%`**（`09` 策C 沿岸帯）。 |
| **Boundary Seam Jump** (`↓`) | 「本物の走査線」と「AI が埋めた走査線」が接する 1px 境界での明るさの段差です。小さいほど継ぎ目（シーム）が目立ちません。 | `0.020〜0.029` 程度（全輝度レンジ `1.0` に対して `2%` 台の自然な接続）。 |
